## 二、数据边界：0907 表能用哪部分、不能进哪部分（硬规则）

## 四、异常规则（结构化判断）

| 规则 | 判定 | 严重度 |
|---|---|---|
| below_lpp | 监测价 < 对应包装 LPP | high（立即进异常队列，不等下周期） |
| price_down | 较上一 **live** 监测日下降 | medium |
| price_up | 较上一 **live** 监测日上涨 | low |
| new_listing | 上日空白、本日有报价 | info |
| delisted | 上日有报价、本日空白（疑似下架，需复核） | medium |
| pack_changed / unverifiable / insufficient_evidence | 0920 采集期启用 | — |

- **第一个 live 批次（0920 基线）没有对比基线**，price_down/up/delisted/new_listing
  从第二个 live 批次（09-22）开始才有意义；below_lpp 从基线批即可生效。
- below_lpp 只对映射到 single/double/case 的 SKU 生效（0907 三列口径）；
  `other` 表外 SKU（如祥云蓝色礼盒）只记录、不判断。
- 0907 对账结论（仅作规则正确性验证，不进入监控输出）：规则判出 63 个破价格，
  覆盖人工标红绝大部分；5 处人工标红规则不认可；1 处人工漏标被规则抓出。

## 五、0920 采集规范（本方案核心）

### 5.1 监控 / 证据 / 判断 三段分离

| 阶段 | 职责 | 产物 | 纪律 |
|---|---|---|---|
| 采集（monitor） | 在京东 App 打开**正确商品**页面，拿原始材料 | 截图 + uiautomator 文本 dump + 页面 URL + 时间戳 | 只记录，不口算判断；截图时间即采集时间 |
| 证据（evidence） | 原始材料只读归档 | `evidence/日期/…` + `evidence_text/日期/…` | 归档后不再改写；判断阶段只能读 |
| 判断（judge） | 离线从证据解析价格 → 写库 → 跑 rules.py | observations + anomalies | 不接触京东客户端；判断错了改判断，不改证据 |

### 5.2 商品确认：店铺 + 完整商品名搜索（防搜错）

**店铺口径：本任务 180 个商品全部来自「拉菲罗斯柴尔德葡萄酒官方旗舰店」。**
搜索结果里同系店铺至少有 3 家：官方旗舰店、京东自营专卖店、海外京东自营旗舰店，
卖相近商品但价格体系不同——**只认官方旗舰店的链接**，其余店铺的商品一律不采。

- 搜索关键词 = **完整商品名**（品牌 + 年份 + 容量/规格 + 版本），禁止「拉菲」
  这类短词——系列里名称相近的商品极多（传奇/传说/巴斯克精选/珍藏…），
  短词搜出来的只是相近商品。
- 命中核对「**店铺 + 四要素**」：店铺须为官方旗舰店；商品页标题的品牌、年份、
  容量/规格、版本必须与种子商品一致。任一不符 → `monitor_status=待人工确认`，
  **不入库、不猜**。
- 组合装必须进详情页核对成员明细与数量。
- 联想词出现完全同名商品可以直接用，但同样过「店铺 + 四要素」核对。
- **优先在官方旗舰店店内完成采集**：首次确认店铺后记录店铺 ID 并收藏，
  店内商品列表页可以一次性扫过在售商品（比逐个全站搜索风控暴露小得多）；
  确认通过的商品把京东商品 URL 记入 observations.url，后续批次直接回访。

### 5.3 SKU 全量如实记录（新增，先记录再对比）

0907 表用「单瓶/双支礼盒/整箱」三列记录价格，但这只是对照口径，不是商品的真实销售结构。
京东商品页主图下方的「**共 x 款**」展开后才是该商品的全部 SKU。

> **0920 首次实采纠正（重要）**：原方案写「以巴斯克源自拉菲罗斯柴尔德赤霞珠红葡萄酒为例
> 共 4 个 SKU（单瓶/双支礼盒/整箱/祥云蓝色礼盒）」是**未经实测的假设，已作废**。
> 实采该商品页为「**规格(3)**」，SKU 面板实际是 3 款，**没有**祥云蓝色礼盒：
>
> | # | SKU 原名 | 京东型号编码 | 页面标价 | 到手价 | 映射 |
> |---|---|---|---|---|---|
> | 1 | 巴斯克赤霞珠单支 | 10152168265683 | ¥99（划线价） | ¥94 | single |
> | 2 | 巴斯克赤霞珠双支礼盒装 | 10222897158082 | ¥194（每瓶¥97） | — | double |
> | 3 | 巴斯克赤霞珠整箱装（750ml×6） | 10152168265684 | ¥479（划线价） | ¥474 | case |
>
> 结论：**「共 x 款」是唯一的 SKU 数口径，必须逐商品实测，不得由 0907 三列或任何假设推得。**
> 计划槽位 510（165 单品×3 + 15 组合装）只是**0907 三列口径的预期底数**，不是真实 SKU 总数；
> 实采后以「共 x 款」为准，多出的记 `pack_type=other`，少的记 `no_such_pack` 进待补采。

采集规则：

1. 进详情页后先点「共 x 款」展开 SKU 面板，**逐一选中每个 SKU**，
   如实记录 SKU 原名、价格与证据（SKU 面板截图 + 各 SKU 价格区截图）；
2. **先如实记录，再做映射对比**：全部 SKU 入库后，才按 0907 口径映射
   `单瓶→single、双支礼盒→double、整箱→case`，参与 LPP 对比；
3. **表外 SKU**（如祥云蓝色礼盒）：同样记录价格与证据，`pack_type=other`、
   note 单独备注「0907 表未覆盖 SKU」，不参与 LPP 判断，监控台单独展示；
4. SKU 缺货/灰置也要记录状态（out_of_stock），不能跳过；
5. 某 SKU 在面板中不存在 → `no_such_pack`，进待补采落实。

### 5.4 拟真人采集节奏（京东风控规避）

每采集 1 个商品的完整动作脚本：

1. 回到京东首页，随机滑动 1–2 屏（每次 1–3s）；
2. 进**移动端购物车**，停留 3–8s（有内容就滑一下）；
3. **随机浏览 1–3 个监控商品详情页**（正常浏览：看主图 2–4s、划到评价区 1–2 次）；
4. 搜索完整商品名（或进官方旗舰店店内找）→ 结果页停留 2–5s（必要时滑一屏）；
5. 进目标商品详情页 → 停留 3–6s → 展开「共 x 款」逐 SKU 截图（价格区）+ dump 页面文本；
6. 写库并立刻校验「截图价 = 入库价」。

随机化参数（每次取值都在区间内独立随机）：

| 参数 | 区间 |
|---|---|
| 单次点击间隔 | 0.8 – 2.5s |
| 页面停留 | 2 – 6s |
| 每采 N 个商品后休息 | N = 5 – 8，休息 60 – 180s |
| 单会话时长 | 30 – 60 分钟后长休 |
| 批次总时长 | 按 180 商品估算 3 – 6 小时，可分 2 – 3 段完成 |

纪律：

- 触发验证/滑块：**立即停手**，不连环重试，报告并等待处理
  （教训：上次 motionevent 一笔画太慢被判失败；人工验证比我自动画可靠）。
- 同一商品一天只采一次；失败只重试 1 次，仍失败进「待补采」。
- 搜索频率是风控最敏感的点：能用已确认 URL 直接回访的，不再搜索。

**无障碍树（uiautomator）什么时候可用、什么时候不可用（0920 实测）**
- **不可用**：京东**首页**、**搜索结果页/店铺列表页**等带自动轮播的页面，
  `uiautomator dump` 直接报 `ERROR: could not get idle state.`；此时 harness 的 `tree/labels`
  会返回**上一次成功的陈旧内容**（看起来正常、其实是别的页面），照它点会点错地方。
  关掉系统动画（`window/transition/animator_duration_scale=0`）**不能**解决。
  → 这些页面一律用**截图 + 坐标**（见下）。
- **可用**：**商品详情页**、**SKU 选择面板**，树能读到精确 bounds，可直接 `tap-text`。
- 教训：每次 `tree` 之后要核对返回内容跟当前截图是否一致，不一致就丢掉落回坐标法。

**轨迹验证（当前设为人工）**

  `/dev/input/event4` 属 root:input 0660，shell 写不了 → `sendevent` 路线不通。

- 后续可选自动化路线（待立项）：scrcpy 4.1 的 HID 触摸注入（shell 已在 `uhid` 组，
  Escrcpy 已带 scrcpy 4.1）/ UiAutomator `GestureDescription` 的 on-device 脚本
  （一个 JVM 内完成多段一笔画，可做到 300ms 内）。做成 `fast-stroke` 工具后再恢复自动。

### 5.8 价格口径与商品名口径（0920 23:3x W Sir 定稿）

**① 价格：到手价为主口径，到手价 + 划线价都记；破价规则双口径同时存在，网页可切换**

| 项 | 定稿 |
|---|---|
| 主口径 | **到手价**（成交价） |
| 落库 | `observations.price` = 到手价；`observations.list_price` = 划线价；`deal_price` 兼容保留（= price） |
| 规则 | `anomalies.basis` 区分两套：`deal`（到手价规则，默认）/ `list`（划线价规则）；两套**同时计算、各存一行**，互不覆盖 |
| 页面 | 右上角「破价口径：到手价规则 / 划线价规则」一键切换；首页/商品/异常队列/详情页/导出全部跟随；触发价列按口径取价，另固定展示「到手价 / 划线价」两列供对照 |
| 导出 | `export_excel.export(out, date, basis=...)`，文件名带口径后缀；Excel 里两列价格始终齐全 |
| 默认口径存库 | `settings.pricing_basis = 'deal'`（`?basis=` 可临时覆盖） |

首单实测的差异正是这个开关的价值所在（**同一份数据、两套结论**）：

|---|---|---|---|---|---|
| 巴斯克赤霞珠单支 | 94 | 99 | 99 | **破价 -5** | 持平不破 |
| 巴斯克赤霞珠双支礼盒装 | 194 | —（页面无划线价） | 无 | 不判 | 不判 |
| 巴斯克赤霞珠整箱装 | 474 | 479 | 499 | **破价 -25** | **破价 -20** |

当前基线批结果：**到手价规则 2 条破价 / 划线价规则 1 条破价**。
划线价只在页面确实显示时才记，**不编造**（如双支礼盒装留空）。

**② 商品名：不要求逐字一致，用「组合锚点」确认同一商品；另存保险列**

- 确认依据（四条同时看）：①店铺 = 拉菲罗斯柴尔德葡萄酒官方旗舰店；
  ②品牌一致（巴斯克 / 拉菲罗斯柴尔德）；③品种与规格一致（赤霞珠、750ml 等）；
  ④SKU 面板结构与 0907 三列口径吻合（单支 / 双支礼盒 / 整箱）。
  官方旗舰店普遍使用**店内短名**（省「源自拉菲罗斯柴尔德」），不视为名称不符。

### 5.10 全自动采集驱动器（0921 凌晨建成）

**为什么需要**：180 个商品 × 每个 2–4 个 SKU，靠人手逐屏点不可能完成，
而「如实全量记录」又要求每个 SKU 都有价格与截图。做法是让脚本在手机里跑完整流程，
**价格与 SKU 全部从无障碍树读取**（不是 OCR、不猜、不由模型编）。

**关键发现：京东是单 Activity 应用，包名不能用来判页。** 首页、搜索页、店铺页、
详情页的顶层包名都可能是 `com.jingdong.app.mall/.MainFrameActivity`，必须改用**内容地标**判页：

| 页面 | 判定地标（resource-id） |
|---|---|
| 店内搜索/输入页 | `com.jd.lib.jshop.feature:id/jw`（EditText） |
| 店首页 | `com.jd.lib.jshop.feature:id/r3`（搜索入口，**必须先于结果页判定**） |
| 店内结果页 | `com.jd.lib.jshop.feature:id/nh`（卡片标题，无 r3、无 EditText） |
| 商品详情页 | `com.jingdong.app.mall:id/a3s` 或页面文本「共 N 款」 |

**解析口径（已验证）**

| 字段 | 来源 |
|---|---|
| 京东原始标题 | 详情页最长的含「【旗舰店】」/ 以「拉菲」开头的文本节点 → 写 `observations.jd_title` |
| SKU 名 | `com.jingdong.app.mall:id/a3s` |
| SKU 面板行价 | `com.jingdong.app.mall:id/y9`（按 y 就近配对，容差 70px） |
| 到手价 / 划线价 | `com.jingdong.app.mall:id/qs` / `:id/qu`（**面板价格头**；详情页主价格区是纯文本，不带这两个 id） |
| 京东型号编码 | `com.jingdong.app.mall:id/esy`（`编号: xxxxx`）→ 落成 `url = https://item.jd.com/<编号>.html` |

**流程**：店内搜索页 → 注入完整商品名（ADBKeyboard 广播）→ 点搜索 → 读卡片 →
按**必需词全含**选卡片（品牌＋品种＋系列，命中他牌排除词即淘汰）→ 进详情页 →
点「共 N 款」开 SKU 面板 → 逐个点选规格、读价格头与编号、截图 → 写 payload → `record.py` 写库。

**踩过的坑（都已在代码里修掉，别再犯）**

1. `Path.mkdir(exist_ok=True)` 在本机沙箱下抛 `EEXIST` → 必须先 `if not exists()`。
2. `texts()` 里 `contains`/`pattern` 两个都不给时**返回空列表**——`read_cards` 正好这么调，
   于是「搜索成功但读不到卡片」。已改成「都不给 = 取全部」。
3. 排除词**不能含包装词**（单支/整箱/礼盒装）：京东卡片标题天然带 SKU 标识，
   原先把「单支」当负分，把正确卡片从 6 分扣到 1 分而误判「无匹配卡片」。
4. 注入中文后立刻读无障碍树会拿到**陈旧页**（搜索页/首页/店内列表页拿不到 idle）
   → 点搜索后必须**轮询结果**，读不到就再点一次（已做 3 次重试）。
5. 退栈不能盲目连按 back：会退出店铺。已改成「最多退 3 次 + 掉出店铺自动重进」。
6. macOS **没有 `setsid`**，`nohup setsid` 直接报 `No such file or directory`；
   长时间采集用工具层的后台任务托管，别用 nohup 裸起。
7. **别用长前缀匹配规格名**：`巴斯克霞多丽白葡萄酒750ml*` 同时命中 `750ml*1` 与 `750ml*6`，
   会把第 3 行点成第 1 行。已改成「先精确匹配，再退到末 8 字唯一子串」。
8. **SKU 段名不固定**：同一家店不同商品分别叫「规格(3)」「品种(3)」，别写死。
9. **「面板行价」才是某一行的价，价格头是「当前选中行」的价。** 二者可能因为点空而不一致
   （P0003 曾把 `750ml*6` 的价记成上一行的 888.9，实际应为 2788.9）。
   现已加硬校验：**价格头到手价必须等于该行面板价**，否则该行只记面板价，
   划线价与型号编码一律留空并标 `confidence=低`——宁可少记，绝不张冠李戴。
10. **详情页版式不止一种。** 除了「共 N 款」版式，还有「已选：xxx，1件」版式
    （巴斯克十世年份套装就是这种，没有「共N款」）。判页与面板入口都要两种都认。
11. **判页信号要用详情页专属词**（单品购买 / 组合套装 / 支持送礼物 / 一键送礼 /
    优惠换购 / 新人三单礼 / 店铺近30天 / 图集）。用「加入购物车 + 到手价」会误判——
    店内卡片列表上也有这两个词。
12. **重进店前必须先离开未知页面**：在详情页上那几个首页坐标全是无效点击，整个重进流程会
    静默空转。正确做法是先 back 收掉弹层/大图，再 `am force-stop` + monkey 重开京东回首页。
13. 面板只显示一个规格、价格头没给划线价时，用详情页主价格区那行「¥2899 | 已售11件」
    回填划线价（有且仅当面板只有一个规格时才敢这么配，避免张冠李戴）。
14. **京东会中途把账号踢掉，之后搜索/店内搜索全部被登录页拦下。**
    （0921 约 01:32 实测：`我的`、全局搜索、店内搜索全部跳到 `com.jd.lib.login.feature`；
    搜索结果页显示「登录后，购物更轻松~」+「重新加载」，重载也无效。）
    - 后果：不识别的话整批会一路「页面=other」失败下去——当晚 11 个商品就是这么白烧的。
    - 现已加 `login_wall()/guard_login()`：命中登录页文案或登录模块包名即刻抛 `LoginWall`，
      **整个批次立刻中止**并留失败截图，剩下的靠断点续采，不会把 167 个全烧成失败。
    - 只能人工登录（要短信验证码）。登录后直接重跑同一条命令即可续采。
15. **关键词要能逐级放宽。** 京东店内搜索对过长的名字直接 0 结果
    （P0025「巴斯克瞰御Caneten红葡萄酒2022」实测空手而归）。现在
    `make_spec.py` 为每个商品生成**关键词阶梯**（全名 → 去年份 → 去品类词 →
    去拉丁名 → 品牌兜底），一个关键词没结果就换下一档；
    判定仍靠必需词 + 排除词，不因搜索词放宽而抓错商品。
16. **「源自拉菲罗斯柴尔德」里的「拉菲」不能当必需词。** 那只是家族前缀，京东卡片标题
    未必带（P0030 传奇玫瑰红葡萄酒就会因此永远选不出卡）。巴斯克这类子品牌照旧必需。

## 八、业务口径（0920 23:3x W Sir 定稿）

1. **破价基准**：LPP。below_lpp = 监测价 < LPP。
2. **价格口径**：主口径 = **到手价**；**到手价与划线价都记**；两条破价规则（到手价规则 / 划线价规则）
   **同时存在**，网页与导出可切换（默认到手价）。见 5.8 / 5.9。
3. **渠道范围**：只采京东 App（已验证可行）。如需并采天猫，另立渠道流程。
4. **店铺范围**：只采「拉菲罗斯柴尔德葡萄酒官方旗舰店」；
   京东自营专卖店、海外京东自营旗舰店的同款商品不监控（价格体系不同）。
5. **表外 SKU**（页面「共 x 款」里存在、但 0907 三列口径未覆盖的 SKU）：如实记录价格与证据
   并单独备注，不参与 LPP 判断。
6. **商品名确认**：不要求逐字一致，按「店铺 + 品牌/品种/规格 + SKU 三列结构」组合锚点确认同一商品；
   官方旗舰店的店内短名不视为名称不符；另存 `observations.jd_title`（京东原始标题）作保险。
7. **SKU 数**：以商品页「共 x 款」实测为准，不得由假设推得。
