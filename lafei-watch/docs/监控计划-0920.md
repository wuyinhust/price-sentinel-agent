# 拉菲旗舰店价格监控方案

> 三条铁律：
> 1. 数据库是主记录，Excel 只是导出格式。
> 2. 历史表（0903/0907）只是任务输入与判断基准，不是证据，不上网页、不进导出。
> 3. 网页与导出里的每个价格必须同时满足：①在京东 App 实采；②带截图证据与秒级时间戳；③经离线复核通过。

## 一、数据边界（硬规则）

| 0907 表的内容 | 用途 | 上网页/导出 |
|---|---|---|
| 商品清单、品牌/组合组、规格 | 任务输入 → products / packages 种子 | 是（带溯源行号） |
| 零售价、单瓶/双支/整箱 LPP | 判断基准 → price_rules | 是（基准，非监测价） |
| 0903/0907 的监测价、库存空白 | 仅作待补采线索 | 否 |
| 0907 的三列口径（单瓶/双支/整箱） | SKU 映射对照 | 否（SKU 以京东页面为准） |
| 红/黄人工标记 | 存档参考 | 否 |

执行要求：

1. 0903/0907 监测记录封存（`visible=0`），所有视图默认过滤；其派生异常清空，异常只由 live 批次生成。
2. 待补采清单可用 0907 线索生成，须标注「任务输入线索」，经 live 采集覆盖后才转正。
3. live 批次判定口径：method ∈ 白名单（`p30-harness`、`iphone-use` 等本人实采方式），白名单写死在查询层。

## 二、数据结构（八表）

| 表 | 内容 | 要点 |
|---|---|---|
| products | 商品 ID、品牌、名称、年份/容量/版本、店铺 shop、single/combo、0907 溯源行号、monitor_status | 唯一稳定 ID `P0001…`；只有「已确认」进监控范围；店铺统一为「拉菲罗斯柴尔德葡萄酒官方旗舰店」 |
| combo_members | 组合装成员 | 组合价为整组价 |
| packages | 包装 ID、pack_type（single/double/case/combo_pack/other）、sku_name（京东原始 SKU 名）、existence、来源 | SKU 以京东页面实际为准，表外 SKU 如实记录 |
| price_rules | 零售价、单瓶/双支/整箱 LPP、生效时间、价格条件 | 基准来自 0907；每商品一行，按生效日追加 |
| observations | 监测记录：日期 + 秒级时间戳、商品、包装、sku_name、店铺、到手价 price、划线价 list_price、库存状态、渠道、链接、jd_title（京东原始标题）、证据、采集方式、可信度、visible | 只追加不覆盖；`visible=1` 才上网页 |
| anomalies | 异常类型、basis（deal/list）、触发价、对比规则、差额、严重程度、状态、处理结论 | 只由 live 批次生成；两套口径各存一行，页面可切换 |
| batches | 每批次计划数/实采数、起止时间 | 每次采集一批 |
| settings | 全局键值（`pricing_basis` = 破价默认口径） | 网页切换只改查看口径 |

库存状态枚举：`ok / out_of_stock / not_listed / not_monitored / no_such_pack / unrecognized / blank_legacy（历史空白，仅线索）`。

## 三、异常规则

| 规则 | 判定 | 严重度 |
|---|---|---|
| below_lpp | 监测价 < 对应包装 LPP | high（立即进队列） |
| price_down | 较上一 live 监测日下降 | medium |
| price_up | 较上一 live 监测日上涨 | low |
| new_listing | 上日空白、本日有报价 | info |
| delisted | 上日有报价、本日空白 | medium（需复核） |

- 第一个 live 批次无对比基线：price_down/up/delisted/new_listing 从第二个批次起生效；below_lpp 从基线批即可生效。
- below_lpp 只对映射到 single/double/case 的 SKU 生效；`other` 表外 SKU 只记录、不判断。

## 四、采集规范

### 4.1 监控 / 证据 / 判断 三段分离

| 阶段 | 职责 | 产物 | 纪律 |
|---|---|---|---|
| 采集 | 打开正确商品页，拿原始材料 | 截图 + 界面树 dump + URL + 时间戳 | 只记录，不口算判断 |
| 证据 | 原始材料只读归档 | `evidence/日期/` | 归档后不改写 |
| 判断 | 离线解析价格 → 写库 → 跑 rules.py | observations + anomalies | 不接触京东客户端；改判断不改证据 |

### 4.2 商品确认：店铺 + 四要素

- 只认「拉菲罗斯柴尔德葡萄酒官方旗舰店」。同系还有京东自营专卖店、海外自营旗舰店，价格体系不同，一律不采。
- 核对四要素：品牌、年份、容量/规格、版本。任一不符 → `monitor_status=待人工确认`，不入库、不猜。
- 搜索用完整商品名（品牌+年份+规格+版本），禁止「拉菲」类短词。
- 组合装进详情页核对成员明细与数量。
- 确认通过的商品把型号编码记入 `observations.url`（`https://item.jd.com/<编号>.html`），后续批次按编号回访，不再搜索。

### 4.3 SKU 全量如实记录

- 「共 x 款」展开后是全部 SKU，是唯一权威的 SKU 数口径，必须逐商品实测，不得由 0907 三列或任何假设推得。
- 流程：先展开面板逐一点选、如实记录全部 SKU（原名/价格/截图），入库后再按 0907 口径映射 single/double/case 参与 LPP 对比。
- 表外 SKU：`pack_type=other`，记录价格与证据，不参与判断，单独展示。
- 缺货 SKU 记 `out_of_stock`；面板中不存在 → `no_such_pack` 进待补采。

### 4.4 复核（每批次必做，离线）

- 基线批 100% 复核：截图价 = 库内价、截图商品 = 种子商品（店铺+四要素）、SKU 数量名称 = 页面实际面板。
- 不符 → `confidence=低` + note 记原因 + 进待补采。
- 后续批次抽样 ≥20%，破价与新品必抽。

## 五、口径定稿

### 5.1 价格：到手价主口径，双价都记，双口径规则并存

| 项 | 定稿 |
|---|---|
| 主口径 | 到手价（成交价） |
| 落库 | `price` = 到手价；`list_price` = 划线价（页面没有就留空，不编造） |
| 规则 | `anomalies.basis`：`deal`（默认）/ `list`，同时计算、各存一行 |
| 页面 | 右上角一键切换，首页/商品/异常/详情/导出全部跟随 |
| 导出 | `export_excel.export(out, date, basis=...)`，文件名带口径后缀，两列价格始终齐全 |
| 默认值 | `settings.pricing_basis = 'deal'`，`?basis=` 可临时覆盖 |

### 5.2 商品名：组合锚点确认 + 保险列

- 确认依据（同时满足）：店铺正确 + 品牌一致 + 品种规格一致 + SKU 面板结构与 0907 三列吻合。
- 官方旗舰店用店内短名（省「源自拉菲罗斯柴尔德」），不视为名称不符。
- 保险列：`observations.jd_title` 存京东页面原始标题（一字不改）；型号编码进 `observations.url`。

### 5.3 日常运维命令

```bash
python src/rules.py --reset     # 改价或改规则后重算两套口径
open "http://127.0.0.1:8321/?basis=deal"   # 到手价规则（默认）
open "http://127.0.0.1:8321/?basis=list"   # 划线价规则
curl -o 到手价口径.xlsx "http://127.0.0.1:8321/export.xlsx?basis=deal"
curl -o 划线价口径.xlsx "http://127.0.0.1:8321/export.xlsx?basis=list"
```

## 六、全自动采集驱动器

价格与 SKU 全部从界面树解析，不用 OCR、不猜。

**判页**：京东是单 Activity 应用，包名不能判页，用内容地标（完整地标与资源 ID 表见《使用指南-iPhone与安卓.md》）。

**解析口径**：

| 字段 | 来源 |
|---|---|
| 京东原始标题 | 详情页含「【旗舰店】」的最长文本 → `jd_title` |
| SKU 名 | `mall:id/a3s` |
| SKU 面板行价 | `mall:id/y9`（按 y 就近配对，容差 70px） |
| 到手价 / 划线价 | 面板价格头 `mall:id/qs` / `:id/qu`（详情页主价格区无此 id） |
| 型号编码 | `mall:id/esy` → `url=item.jd.com/<编号>.html` |

**流程**：店内搜索 → 注入完整商品名 → 读卡片 → 必需词全含选卡（命中排除词即淘汰）→ 详情页 → 开 SKU 面板 → 逐个点选规格、读价格头与编号、截图 → payload → `record.py` 写库。

**跑法**：

```bash
python3 tools/make_spec.py --out payloads/spec_all.json   # 生成采集规格
bash tools/run_collect.sh                                 # 开跑（断点续采）
# collect_driver.py 参数：--limit N 灰度 / --pid P0014 单商品 / --force 强制重采
```

前置条件：手机京东 App 处于登录态。产出：`payloads/日期/<pid>.json`、`evidence/日期/*.png`、`logs/collect_日期.log`、断点 `state/collect_日期.json`；失败截图落 `evidence/日期/_fail/`。

已知报错与修法全部收录在《使用指南-iPhone与安卓.md》的报错 recipe（A1–A19）；风控规则见《京东风控避坑指南.md》——开跑前必读。

## 七、监控台与导出

- 首页：开放异常数、最新批次完成率、破价清单、价格/在售变化、待补采数。
- /products 商品清单（最新价 vs LPP，破价红色高亮）；/anomalies 异常队列；/pending 待补采；/evidence-gallery 证据库；/export.xlsx 导出（`?date=` 按批次）。
- 所有视图只展示 `visible=1` 的 live 数据。
- 导出 21 列，含到手价、划线价、京东原始标题；证据列为本地截图超链接。
